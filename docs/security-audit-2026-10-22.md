## 의존성 취약점

처음 `npm audit` 결과는 영향 패키지 33개(critical 1, high 21, moderate 10, low 1)였다. Next·React·Vinext·Vite·Cloudflare 도구 및 관련 전이 의존성을 호환되는 수정 버전으로 갱신했다. 최종 결과는 **critical 0, high 8, moderate 0, low 0**이다. 이는 고유 CVE 수가 아닌 영향 패키지 수다.

남은 8개는 `braces` 재귀 처리 DoS와 그 의존 체인이다. [공식 보안 공지](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm)상 현재 수정 버전이 없으므로 해소됐다고 표시하지 않는다. 이번 빌드의 `dist` JS와 source map에서 해당 패키지 경로는 발견되지 않았고, 업무 API는 입력을 glob 패턴으로 전달하지 않는다. 개발 서버는 loopback에 제한했다. 다만 이것만으로 모든 실행 경로의 비영향을 증명하지는 않는다. 신뢰할 수 없는 프로젝트·glob 패턴으로 개발·빌드 도구를 실행하지 말고 상위 패키지의 수정 버전을 추적해야 한다. 최종 목록: `deliverables/dependency-audit.json`.

## 라이선스와 상용 배포

고지는 설치된 원본 라이선스·저작권·NOTICE를 모은 것으로, 소프트웨어 전체를 새로 라이선스하지 않는다. MIT/BSD 등의 고지를 보존하고 MPL/LGPL 구성요소를 재배포하는 경우 해당 소스 제공 등 조건을 확인해야 한다. 일부 항목은 빌드 도구의 네이티브 패키지여서 실제 배포 포함 여부에 따라 의무가 달라진다. 라이선스 원문이 없는 수동 검토 항목은 패키지 버전과 소스 링크를 기록했다. API 서비스 약관, 참고 디자인·로고·메뉴 이미지 권리는 오픈소스 패키지 라이선스와 별개다. 상용 사용 전 이 항목들을 검토해야 한다.

고지 갱신: `python scripts/generate-notices.py`. 결과물은 저장소·웹·Android 로컬 자산에 포함한다.

## 검증

- 단위·API 보안 테스트 30개 통과. 타입 검사 통과.
- 기존 카페·보험청구 HTTP 통합 검사 6개 묶음, 작은 글씨 전달 2개 분야 통과.
- 실제 로컬 서버의 입력·바이트 상한·미지원 형식·토큰·헤더·숨김 파일 차단·라이선스 제공 검사 5개 묶음 통과.
- 웹 production 빌드 및 Android 1.3(versionCode 4) APK 빌드 성공. APK manifest에서 `usesCleartextTraffic=false` 확인.
- APK SHA-256: `4abd74663f1f0bb22d6bf016fab24ff2645c350ec9b54ed18785e4902588fab8`.
- 알려진 키 검사와 패턴 검사 결과는 `deliverables/security-secret-scan.json`에 저장한다. 키 값은 보고서에 기록하지 않는다.
- 로컬 브라우저의 프로필 화면·라이선스 화면을 열어 콘솔의 알려진 자격증명 패턴을 검사했다. 관찰 범위를 벗어난 모든 화면·향후 로그의 무노출을 보장하는 것은 아니다. 배포 후 확인 결과는 별도 결과 JSON에 기록한다.
- 이번 점검으로 유료 AI 호출을 추가 실행하지 않았다. 기존 AI 성공·실패 대체 흐름 테스트를 유지했다.

## 실제 운영 전에 남은 작업

익명 공개 시연 API에는 IP별·전체 호출 제한이 있지만 이용자 인증이 없다. 공격자가 제한된 AI 예산을 소진할 가능성이 남는다. 실제 운영에는 인증·게이트웨이 보호, 제공사 청구 상한, 장애 모니터링과 사용자 데이터 정책이 필요하다. CORS를 인증 수단으로 간주하지 않는다. 상용 출시에는 release 서명 관리와 실제 Android 기기 검증도 필요하다.
